# Outcome vs Activity Task Analysis Reference

This reference provides detailed criteria for distinguishing outcome-focused tasks from activity-focused tasks.

## The SMART Test for Outcomes

A good outcome-related task name passes the SMART test:

- **S**pecific - Clearly defined result
- **M**easurable - Can verify completion
- **A**chievable - Concrete deliverable
- **R**elevant - Meaningful business result
- **T**ime-bound - Has or implies deadline

## Red Flags for Non-Outcome Tasks

Watch for these patterns that indicate activity-focused (non-outcome) tasks:

### 1. Action Verbs Without Results
- "Review...", "Check...", "Follow up...", "Update...", "Meet...", "Discuss..."
- These describe activities, not outcomes
- **Fix**: Add what the review/meeting should achieve

### 2. Vague or Generic Terms
- "Daily Tasks", "Weekly Review", "General Maintenance"
- No specific result mentioned
- **Fix**: Break down into specific outcomes

### 3. Abbreviations or Code Names
- "RSP", "MVJ", "BOQ", "Project X"
- Without context, unclear what outcome is
- **Fix**: State the desired result with the project

### 4. Questions or Open Inquiries
- "Lead Generation?", "NGO"
- Questions don't state outcomes
- **Fix**: Turn into statements of desired outcomes

### 5. Names Without Action
- "Porche", "Prowis", "Satya sai - BOQ"
- Just naming a project/client without the outcome
- **Fix**: Add what needs to be delivered/achieved

## Conversion Examples

### Example 1: Meeting Tasks
❌ **Non-Outcome**: "Meet with client"
✅ **Outcome**: "Secure signed agreement from client by Oct 20"

### Example 2: Review Tasks
❌ **Non-Outcome**: "Review financial documents"
✅ **Outcome**: "Approve Q3 financial report for board presentation"

### Example 3: Update Tasks
❌ **Non-Outcome**: "UPDATE PAYMENT"
✅ **Outcome**: "Process ₹50K payment to vendor XYZ"

### Example 4: Project Tasks
❌ **Non-Outcome**: "Porche project"
✅ **Outcome**: "Complete Porche brand strategy deck by Friday"

### Example 5: Follow-up Tasks
❌ **Non-Outcome**: "Follow up with Alwyn's team"
✅ **Outcome**: "Receive final approval from Alwyn's team on design mockups"

### Example 6: Daily Lists
❌ **Non-Outcome**: "Daily Tasks"
✅ **Outcome**: Should be broken into specific outcomes like:
- "Complete salary processing for 20 employees"
- "Book bus tickets for 3 team members"
- "Post inktober artwork on social media"

## Edge Cases

### When Abbreviations Are OK
If the abbreviation is well-known in the team AND the task describes an outcome:
✅ "Finalize MVJ BOQ for client approval" - OK if team knows MVJ
✅ "Submit RFP response by deadline" - OK if RFP is standard term

### When Activity Words Are OK
Activity words are acceptable if the outcome is clear:
✅ "Review and approve 10 designer applications by EOD" - Clear outcome
✅ "Meet with investors and secure $100K funding" - Clear outcome
✅ "Update website with new product launch by Monday" - Clear outcome

## Context Matters

When task names are ambiguous:
1. Check the task description/details
2. Look at linked projects or related tasks
3. Consider the task type and urgency fields
4. If still unclear after checking context, mark as non-outcome

## Special Cases for This Database

Based on the "Running Task Owners" database structure:

- **Type of task** field can provide context
- **Next Step** field might clarify the outcome
- **Description** field often has critical context
- **Project** relations might clarify scope

Always fetch the full task page if the name alone is insufficient for classification.
